# Evals

HealthScan's AI output is tested the way finance engines are: against a golden set, with
floors that only move up. Every tier reads the same golden set in [`golden/cases.ts`](golden/cases.ts).

| Tier | Command | Network | Runs | What it scores |
|---|---|---|---|---|
| **Offline** | `npm run evals:offline` | None | Every PR (CI) | The deterministic pre-LLM pipeline: classification, ingredient extraction, noise rejection, allergen survival, EDC detection |
| **Replay** | _planned (M3)_ | None | Every PR | Recorded Gemini responses through the post-processing (schema validation, token join, allergen merge) |
| **Live** | _planned (M3)_ | Gemini | Prompt/schema changes, nightly | Plain-English name accuracy, risk-family recall, safety floor, hallucination rate, latency, cost |

## Rules

- **Floors are a ratchet.** [`thresholds.json`](thresholds.json) holds the minimum score for each
  metric. CI fails below it. Raise the floor in the same PR that improves the metric. Never lower
  it without a written reason in the PR.
- **Results are committed.** `results/offline.md` is regenerated by the eval run, and CI fails if the
  committed copy is stale, so every PR diff shows its effect on quality.
- **Expectations are conservative.** A golden case asserts only what a careful human label-reader
  would insist on. Acceptable names are lists, not single strings.
